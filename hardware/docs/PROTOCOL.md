# Otter 身体协议草案 v1

状态：模拟器中已实现；真实串口与 ESP32 完整接收端尚未实现。

## 职责

- 主机发送有明确意义的指令：表情、预设动作、停止。
- 设备上报触摸等输入，并返回接收结果。
- 显示、触摸反馈、动作时序在设备本地执行。
- 模型不直接输出 GPIO、电机电压或未标定的角度。

拟采用 UTF-8 JSON，每条消息独占一行。当前传输是内存模拟，没有真的编码为串口字节流。

## 主机指令

```json
{
  "v": 1,
  "session": "sim-1-example",
  "id": "cmd-12",
  "type": "perform",
  "expires_at_ms": 1792500002000,
  "payload": {
    "action": "nod",
    "duration_ms": 1400,
    "strength": 0.65
  }
}
```

示例时间仅用于说明格式，不能直接复制为现在有效的指令。

| 字段 | 含义 |
|---|---|
| `v` | 协议版本，目前为 1 |
| `session` | 每次重新连接都更换的会话 ID |
| `id` | 同一命令的重试沿用 ID；新动作使用新 ID |
| `type` | `express`、`perform` 或 `stop` |
| `expires_at_ms` | 模拟时钟中的绝对过期时间，单位毫秒 |
| `payload` | 类型对应的参数 |

### 表情

`express` 的参数：`mood`、`duration_ms`。

支持 `idle`、`listening`、`thinking`、`speaking`、`happy`、`sleeping`。`offline` 只由连接状态产生。开心是临时表情，结束后恢复之前状态；其他表情持续到下一个明确状态。休息时拒绝开心和动作，发送 `idle` 或本地长按可唤醒。

### 动作

`perform` 的参数：`action`、`duration_ms`、`strength`。

- 动作：`nod`、`look_left`、`look_right`、`center`。
- 时长范围：600～2500 毫秒。
- 幅度系数：0.1～1。
- 模拟限位：左右 ±30°、俯仰 ±18°。**这是预览参数，不是 SC09 的真实标定值。**
- 新动作从当前姿态开始，替换正在执行的动作，不在设备侧堆积动作序列。

### 停止

`stop` 停止当前轨迹并保持当前姿态。界面的“停止动作”直接停止本机模拟，同时清除模拟发送队列。

真实硬件必须实现独立的停止策略和失联看门狗，不能把这个本地模拟按钮当成物理急停。实际是否保持力矩，要结合结构和电源决定，不能直接断电导致头部坠落。

## 返回与输入

返回 `type: "ack"`，包含原始 `id`、当前 `session`、`status` 和可选 `reason`。

状态：`applied`、`duplicate`、`degraded`、`rejected`。确认“开始执行”不等于动作已经完成；当前模拟不发送独立的动作完成消息。

设备触摸：`type: "input"`，`payload.kind: "touch"`。长按在本地切换休息并记录对应事件。

## 已实现的规则

- 校验版本、会话、消息 ID、类型和数值范围。
- 拒绝过期以及有效期异常长的指令。
- 当前会话最近 128 个 ID 去重；ID 相同即使参数改变也不会再执行。
- 主机最多保留 32 条待发送指令，日志最多 120 条。
- 断线时清队列、停动作；重连建立新会话，拒绝旧会话消息。
- 无运动能力时用表情回应，返回 `degraded`。
- 不在离线期间积压主机动作。

## 真实硬件接入前必须补齐

1. **时钟基础**：浏览器里主机和设备共享时钟，ESP32 的 `millis()` 与 Mac 的 Unix 时间不同。不能直接比较当前 `expires_at_ms`。正式适配器需要握手同步，并转换为设备单调时钟截止时间；同步失效时拒绝动作。处理时钟回拨和误差窗口。
2. **串口帧处理**：长度上限、部分消息、超长消息丢弃、换行恢复、非法 JSON、字符编码、串口重连。
3. **握手**：设备身份、固件版本、能力清单、会话确认。握手完成前只允许探测，禁止动作。
4. **重试**：超时重试必须沿用同一 ID；明确最大重试窗口。128 项缓存是原型限制，正式版须覆盖整个重试窗口，或采用单调序号防止旧命令再次执行。
5. **断线检测**：设备端用单调时钟运行心跳看门狗；主机关闭、睡眠或拔线时停止运动。当前模拟是直接通知断开，无法证明真实断线检测正确。
6. **标定**：舵机 ID、协议型号、中心角、范围、速度、动作曲线、硬限位、供电与堵转情况。
7. **驱动**：V2 屏幕驱动、触摸输入和 SC09 总线控制。浏览器绘图不可直接复用。
8. **回归**：在真实设备上重复冷却、断线、旧会话、去重、过期和停止验收。

串口自检固件仅用于 `PING` / `PONG` 连通性测试，与此协议有意分开，避免把未接入的硬件当成协议已经验证完成。
