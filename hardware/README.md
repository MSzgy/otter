# Otter 硬件预演台

这是独立的本地教学项目，存放在 `otter` 仓库的 `hardware/` 目录，但与 Otter 应用没有代码、运行时、模型或数据库依赖。目的是在 ESP32 到货之前验证表情、互动和消息处理规则。它不会读取 Otter 数据，不连接真实设备，也不调用 AI。

## 启动

需要 Node.js 20 或以上。没有第三方依赖，不需要 `npm install`。

```sh
cd /Users/zouguoyang/Developer/otter/hardware
npm start
```

浏览器打开 <http://127.0.0.1:4178>。终端按 `Ctrl+C` 停止。端口被占用时：

```sh
OTTER_LAB_PORT=4179 npm start
```

只监听本机回环地址；不向局域网开放。所有界面、字体和代码都使用本地资源。

## 第一次玩什么

1. 点“摸摸头”，观察立即眯眼、随后点头、最后恢复原状态。
2. 把“开心停留多久”改成 4 秒，再试一次。
3. 按住预览中的头顶一秒进入休息，再长按唤醒。也有独立按钮可用键盘触发。
4. 点击“演示一次对话”，预览认真听、思考、说话和点头。它只是预设演示。
5. 打开“只有屏幕”，点头请求会改用开心表情回应。
6. 点击“重复发一次”“让动作过期”“断线后重连”，展开通信记录观察结果。
7. 点击右上角“跟着学”，按第一课练习。

界面支持横屏 320×240 与竖屏 240×320 预览、动作停止、参数调整、演练记录导出。这里的尺寸是像素，不代表浏览器上显示的物理英寸。

## 文件怎么读

| 文件 | 职责 |
|---|---|
| `index.html` / `style.css` | 页面布局与外观 |
| `app.mjs` | 把按钮和页面显示接到模拟器 |
| `src/body.mjs` | 模拟 ESP32：本地触摸、表情、动作和接收校验 |
| `src/lab.mjs` | 模拟 Mac、消息延迟、演练和事件记录 |
| `src/protocol.mjs` | 指令格式、允许的动作与输入校验 |
| `src/face.mjs` | 浏览器里的表情绘制 |
| `docs/LESSON-01.md` | 第一课和动手练习 |
| `docs/PROTOCOL.md` | 协议草案、迁移注意事项 |
| `docs/HARDWARE-ARRIVAL.md` | 到货后的验收顺序与资料 |
| `docs/LESSON-02-SCREEN.md` | 第二课：真实屏幕上的表情与触摸 |
| `docs/LESSON-03-SOUND.md` | 第三课：用板载喇叭发声 |
| `docs/LESSON-04-SERVO.md` | 第四课：供电、总线协议、编号与第一次转动 |
| `firmware/serial_probe/serial_probe.ino` | Arduino 串口自检入门固件 |
| `firmware/otter_face/` | 真实板卡固件：表情、屏幕触摸、内置声音和 USB 指令 |
| `scripts/face-control.py` | 从 Mac 向真实板卡发送白名单指令 |
| `scripts/servo-bus.py` | 通过舵机控制板（跳线 B）扫描、读取、慢速转动舵机和修改编号 |

## 验证

```sh
npm run check
npm test
```

测试使用可控制的时钟，验证过期、重复、旧会话、离线本地反馈、睡眠、能力降级、动作限幅、冷却、停止和队列边界。结果不等同于真实硬件通过验证。具体运行记录见 `docs/VERIFICATION.md`。

## 已实现与尚未实现

已实现的是浏览器中的设备模拟、交互预览、协议草案和第一课。主机模拟与设备模拟共享一个时钟，这让逻辑测试可重复。

尚未实现：

- Otter 正式应用接入；当前只使用预设情景，没有修改原仓库。
- 真正的 USB 串口传输与设备发现。
- ESP32 的屏幕、触摸和舵机驱动，以及完整协议解析。
- 真实电源、电机噪声、承重、触摸片敏感度与外壳验证。
- 真实设备时钟同步、重试窗口内完整去重、串口断帧恢复与心跳看门狗。

浏览器 Canvas 绘制不能直接烧录到 ESP32。可以迁移的是表情设计、状态、时序与消息意图；实际绘制和驱动需要按 V2 板卡示例实现。

串口自检 `.ino` 只接受 `PING` / `HELP`，不是预演台的 JSON 协议固件。当前环境未安装 Arduino 工具链，尚未针对 ESP32 编译或烧录；到货后先配置官方工具链，再编译与实测。

## 与 Claude Code 的开发隔离

本目录随 `otter` 仓库一起做版本管理，但不修改 Otter 应用的依赖、Electron 入口、AI 交接代码或项目数据。后续集成应在交接功能稳定后单独安排，并保留当前纯模拟适配器用于回归测试。

`.tools/`（本机 Arduino 工具链，约 7 GB）、`output/` 和 `backups/`（原厂 Flash 备份）不入库，只保存在本机；原厂备份需要另行妥善保存。
